# Architecture: plugin hooks (bash_guard, brief_guard)

Detail moved out of CLAUDE.md. Rule for allow exceptions: `hook-allow-fail-closed.md`.

- Hooks (`plugin/hooks/hooks.json` -> `bash_guard.py`, since 1.6.0): PreToolUse guard on Bash that hard-denies git write ops (`add/commit/push/reset --hard/rebase`) and lint/test commands for SUBAGENTS (previously prompt-only rules in work/work-simple), and returns "ask" to the main session for `git push` and lint/tests unless `MONOLYNX_AUTOPUSH`/`MONOLYNX_AUTOTEST=true`. `glab mr create` follows the same split: deny for subagents, "ask" for the main session unless `MONOLYNX_AUTOMR=true`. Since 1.13.0 `glab mr merge|accept` and `gh pr merge` do too (unless `MONOLYNX_AUTOMERGE=true`), while `glab mr approve` and `gh pr review --approve` are deny for subagents and always "ask" for the main session - approval is a human decision no flag removes. Main-session `git add/commit` pass through to the normal permission system. Missing `agent_id` in hook input is treated as main session (safe default). Read-only lint exception (MON-176, narrowed in MON-207): only a subagent gets allow for `ruff check --no-fix` and `ruff format --check|--diff`, directly, via `docker compose exec [-T] app`, or via `docker compose ... run` with `-v` from the project root and no `--entrypoint`/`--privileged`/`--user`; bare `ruff check` and `docker run <image> ruff` fall back to the lint/test rule, and the main session gets "ask" for them unless `MONOLYNX_AUTOTEST=true`. Since 1.8.0, an explicit allow-list (`is_tmp_cleanup`, checked before the `DESTRUCTIVE` loop) lets `rm -f` on a `*.log`/`*.txt`/`*.md` file under `/tmp` or `/private/tmp` - subdirectories included, so it covers the session scratchpad - through unprompted for both main session and subagents, deliberately without `-r`/`-R`/`--recursive` and fail-closed on anything else (compound commands including newline/CR as a statement separator, `..`, `$`/`~` shell-expansion in any argument, a bare directory, paths outside `/tmp`). The `rm` rule in `DESTRUCTIVE` parses flags instead of enumerating spellings, so `rm -R`, `rm --rec`, `rm -d` and `rm -i -rf /` are caught too - MON-147. Since 1.8.2 (MON-174) the `rm -rf` target decides: a target under `/tmp`, under the project root (`git rev-parse --show-toplevel` from the hook's `cwd`, so a dispatcher worktree counts) or under any `.claude` directory passes without a prompt for main session and subagents alike (never the root of those directories itself); a target outside them is a hard `deny` for everyone; an unverifiable target (`$`/`~` expansion, glob, compound command) keeps the old ask/deny. Also since 1.8.2 (MON-173): with `MONOLYNX_SPRINT_RUN=1` the hook never returns `ask` (nobody would answer in a background session) but `deny` with an instruction to use a non-destructive variant or end the turn with `SPRINT-RUN STOP`. MON-232: a simple-form call of `python3 <dir>/scripts/monolynx_op.py <op> ...`, `python3 <dir>/scripts/monolynx_transport.py ...` or `monolynx ...` / `mnx ...` exits the hook with no decision (`monolynx_call_kind`, checked right after `is_tmp_cleanup` and before every deny/ask rule), for main session and subagents alike and also under `MONOLYNX_SPRINT_RUN=1`, so words inside an argument (a comment body containing a git or test command) are not taken for a command; there is no explicit allow, reads and writes both fall back to the client's normal permission system like MCP calls. Fail-closed: any of `| ; &`, backtick, newline/CR, `$`, `~`, `<`/`>`, a glob character or a parenthesis `(` `)`, a script with another file name or outside a `scripts` directory, `--yes`/`-y`, and `login`/`logout`/`set`/`unset`/`delete`/`remove` within the first three CLI words keep the old rules. `MONOLYNX_READ_OPS` in the hook is a copy of `READ_OPS` from `monolynx_op.py`, kept equal by `tests/unit/test_bash_guard.py`. MON-249: the hook returns its first explicit `allow` (`permissionDecision: "allow"`) for exactly two commands, `git fetch origin <B>` and `git merge --ff-only origin/<B>`, for main session and subagents alike and also under `MONOLYNX_SPRINT_RUN=1`; `<B>` is `MONOLYNX_BASE_BRANCH`, then `MONOLYNX_MR_TARGET`. Fail-closed: both unset or both set and different means no exception, `<B>` must match `^[A-Za-z0-9][A-Za-z0-9._/-]*$` without `..`, the command must be exactly those four tokens, and any of `| ; &`, backtick, newline/CR, `$`, `~`, `<`/`>`, `* ? [ ] { } ( )`, a quote or a backslash disables it; another branch, a missing `--ff-only`, `--no-ff`, `--squash`, `-s`, `-X`, a refspec, `git -C`, a compound command and `pull`/`reset`/`rebase`/`checkout` keep the old rules. The explicit `allow` removes the prompt in non-auto permission modes, never overrides deny/ask rules, and has no documented precedence over the auto-mode classifier, so the guarantee in auto mode comes from the `--allowedTools` rules of `sprint-run`. MON-251: a simple-form call of `python3 <dir>/scripts/test_lock.py [--timeout N] -- <command>` is unwrapped first, before `is_tmp_cleanup` and every other rule, and judged by exactly the rules of the bare `<command>`, exceptions included (lint/test: deny for subagents, "ask" for the main session unless `MONOLYNX_AUTOTEST=true`; git, MR and destructive rules too) - this is not an exception and not an allow, the wrapper opens nothing. Fail-closed: a shell-syntax character (`| ; & $ ~ < >`, backtick, newline, glob, parenthesis), a missing `--`, a foreign flag, another script name, a script outside a `scripts` directory, `..` or a doubled wrapper means no unwrapping, and the old rules judge the whole string. Second hook `brief_guard.py` (`UserPromptSubmit`, since 1.7.0): the first prompt of a session that is a bare imperative with no contract ("napraw build", "w pliku X dodaj Y"; imperative verb PL/EN within the first 60 chars) gets the `brief` skill injected as `additionalContext` with the prompt as `$ARGUMENTS` (mode `auto`, default), so the agent opens with a contract proposal; `MONOLYNX_BRIEF_GUARD=block` rejects the prompt (exit 2) with a message pointing to `/monolynx:brief <prompt>` instead, `off` disables. One reaction per session (marker under `~/.cache/monolynx/brief-guard/<session_id>`); slash commands, ticket keys, questions, prompts > 200 chars and prompts with contract words pass. Tests: `tests/unit/test_bash_guard.py`, `tests/unit/test_brief_guard.py`
