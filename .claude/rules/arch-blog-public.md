# Architecture: public blog routes, AI layer, landing

Detail moved out of CLAUDE.md. Service: `arch-blog-service.md`. Blocks, chart, lint: `arch-blog-blocks.md`.

**Public blog** (`blog.py`, `blog_ai.py`): two routers with prefix `/blog`, both registered in `main.py` unconditionally (not gated by `SKIP_LANDING_PAGE`), with no session and no RBAC: `blog.py` serves the HTML pages and attachments, `blog_ai.py` (MON-258) the markdown twins `/blog/index.md` and `/blog/{slug}.md`. A post is a wiki page with `is_public=True` plus its `BlogPost` row (MON-254); the routes join the two explicitly (`BlogPost.page_id == WikiPage.id`) and filter `WikiPage.is_public` in SQL, so a private page, an unknown slug and a public page without a `BlogPost` row are all 404, never 403.
- `GET /blog/` - post list through `services/blog.py::list_public_posts`, 20 per page, ordered by `published_at DESC` (then `slug`), so editing an older post does not reshuffle the list. The teaser is `BlogPost.description`; when it is empty the route falls back to a summary extracted from the page content with the block markers removed first (`extract_summary(strip_block_markers(content))`, MON-255, so an alert marker like `[!TLDR]` never shows up in a teaser), read in parallel (`asyncio.gather`) through `blog_ai.load_post_content`, the in-process content cache shared with the feeds (MON-272, described under Feeds below). Since MON-260 the content of every card is read, also when `description` is set, because the same single read (`_fetch_card_data`) gives the reading time (`reading_time_minutes(render_post_markdown(content))`); a MinIO error degrades that one card (`reading_time=None`, teaser = `description` or empty) and the list still answers 200. The date shown is `published_at`, falling back to the page's `created_at`. Filters (MON-260): `?tag=` and `?lang=` are passed to `list_public_posts`. A `lang` from `POST_LANGS` (`pl` / `en`) is only the filter of posts by content language; a missing or other value means no filter. The interface language is a separate query parameter, `ui` (`pl` / `en`, MON-271), which never filters the list; without a valid `ui` the interface falls back to the valid `lang` filter and then to `en`, so an old `?lang=pl` link behaves as before. The links generated on the list (pagination, tags, the language filter, "clear filter") keep `ui` when it was given; the canonical does not carry it. An empty `tag` means no filter; a tag rejected by `is_valid_tag()` answers 200 with an empty list and never reaches the database (a NUL byte in the parameter would make PostgreSQL fail), and it does not enter the context or any generated URL. All list URLs are built by `_index_path(tag, lang, page)`: query order `tag`, `lang`, `ui`, `page`, values through `urlencode`, `page` only when above 1 (so page 1 is `/blog/?tag=x`, never `page=1`). Each item of `posts` keeps `title`, `slug`, `published_at`, `summary` and gains `tags`, `reading_time` (int or `None`), `cover_image_url` (relative path from `get_cover_urls`, or `None`) and `lang`; the new context keys are `filter_tag`, `filter_lang` (the active valid filters or `None`), `canonical_url` (absolute, `{APP_URL}` + `_index_path` of the current page with its filters, so each pagination page is its own canonical instead of always `/blog/`), `prev_url` / `next_url` (relative, filters kept, `None` at the ends) and `lang_switch_url` / `lang_switch_url_en` (read by the layout's language switch; since MON-272 they change only the interface language: `_index_path(filter_tag, filter_lang, ui="pl"|"en")`, so the `tag` and the `lang` filter are both kept and only `ui` is set, e.g. `/blog/?tag=x&lang=en&ui=pl`). `templates/blog/index.html` renders `<link rel="canonical">` and, in `{% block head %}`, `<link rel="prev">` / `<link rel="next">` with `app_url` prepended, loads `static/blog/blog.css` only (no `blocks.css`), and shows the language filter (all / PL / EN), the active tag with a "clear filter" link, and cards whose tag links keep the language filter. The response goes through `blog_ai.conditional_response` (`media_type="text/html; charset=utf-8"`): `ETag` + `Last-Modified` and 304 on a matching `If-None-Match`, with `last_modified` as the newest `page.updated_at` among the posts of the current list page, or 1970-01-01 UTC for an empty list
- `GET /blog/{slug}` - lookup by `BlogPost.slug` through `get_public_post_by_slug`: the current slug renders the post (200), a slug from `previous_slugs` of a public post answers 301 to `/blog/{current slug}` with the query string preserved (`?lang=`), anything else is 404, a slug of the wrong shape included (e.g. `/blog/%00`, MON-271: rejected by `get_public_post_by_slug` before any query). There is no fallback to the wiki slug. Content goes through `render_post_html()` (`services/blog_blocks.py`, MON-255: markdown plus the post block renderers, sanitized with `nh3`); `render_markdown_public()` stays in `services/wiki.py` with unchanged behaviour (the shared markdown renderer followed by `nh3.clean()` with an allow-list of tags, attributes and URL schemes), but nothing in `src/` calls it any more (only its tests do). A MinIO error while reading the content is mapped to 404. `templates/blog/page.html` has no inline `<style>` block any more (MON-260): the post typography, layout, table of contents, footer and list-card styles live in `static/blog/blog.css`, loaded BEFORE `static/blog/blocks.css` (both use `.blog-content ...` selectors and the block styles must win); `static/blog/blocks.js` (copy button, video, diagrams, terminals, graphics and table of contents; all served under `/static/blog/`) is the LAST script of `{% block head %}`, after the per-post graphic scripts and Mermaid (MON-272: `defer` scripts run in document order, and `blocks.js` needs the components and the library registered before it starts). Since MON-257 the route also computes `collect_block_assets(content)` and passes `has_diagram` (bool) and `graphics` (list of names from `BLOG_GRAPHICS`) to the template, which loads the Mermaid library from the CDN only for a post with a diagram and the `static/blog/graphics/<name>.css|.js` pair only for a post that uses that component (details under `services/blog_blocks.py`). Interface language (MON-260): `?lang=` when it is `pl` / `en`, otherwise the post's own `lang` (before, a missing `?lang=` meant `en`). Breadcrumbs, child pages and backlinks list only `is_public` pages and link by `BlogPost.slug`. Meta description and Open Graph come from `description` (fallback: the content summary, `extract_summary(strip_block_markers(content))`), `article:published_time` from `published_at` (fallback `created_at`), and `og:image` / `twitter:image` from the cover attachment when `cover_attachment_id` is set and the attachment still belongs to the page (absolute URL of the attachment route below; otherwise the layout's default image). Content negotiation (MON-258): when the `Accept` header lists the exact media type `text/markdown` (matched case-insensitively by `blog_ai.wants_markdown()`; `*/*` and `text/*` do not trigger it, and neither does `text/markdown;q=0` or an unparsable `q`), the route returns the markdown twin through `blog_ai.markdown_twin_response()`, the same document and the same `ETag` as `/blog/{slug}.md` (200 or 304), with `Vary: Accept` and no `Link` header. The HTML response goes through `blog_ai.conditional_response` (MON-260; `media_type="text/html; charset=utf-8"`, `last_modified` = `page.updated_at`), so it is 200 or, on a matching `If-None-Match`, 304 with an empty body; both carry `ETag`, `Last-Modified`, `Vary: Accept` and `Link: <{APP_URL}/blog/{slug}.md>; rel="alternate"; type="text/markdown"`, and the 301 for an old slug carries `Vary: Accept` too and still points at `/blog/{current slug}`, also when markdown was requested. A 404 is a plain `HTTPException` with neither `Vary` nor `Link`. The template context gains `md_url` (the absolute `.md` address) and `json_ld` (the string from `dump_jsonld(build_post_jsonld(...))`, with `wordCount` counted on `render_post_markdown(content)` and `image` set to the cover URL when there is one); `templates/blog/page.html` renders them in `{% block head %}` as `<link rel="alternate" type="text/markdown" href="{{ md_url }}">` and `<script type="application/ld+json">{{ json_ld|safe }}</script>`, each only when the variable is set. `GET /blog/` passes `json_ld` as well (`dump_jsonld(build_blog_jsonld(...))` over the posts of the current list page), rendered by `templates/blog/index.html` in its own `{% block head %}`. `|safe` is allowed there only because the string was neutralized in Python by `dump_jsonld()`; no JSON is assembled in a template. Post page for people (MON-260): the context also carries `post_lang`, `description` (`post.description`, shown under the title only when set), `author_name`, `last_verified_at`, `tags`, `reading_time` (`reading_time_minutes(render_post_markdown(content))`), `toc` (`extract_toc(content_html)`, objects with `level`, `id`, `text`; empty below 3 headings), `related` (max 3 dicts `{title, slug, description, published_at, tags}` from `list_related_posts`), `translations` (dicts `{lang, slug, title}` from `list_public_translations`, titles fetched in one query), `hreflang_links` (dicts `{lang, url}` with absolute URLs, the current post first and then its translations; an empty list when there is no public translation) and `lang_switch_url` / `lang_switch_url_en` (`/blog/{slug}?lang=pl|en`, read by the layout). The template treats every one of these keys as optional and renders no empty element for a missing value. It renders `<link rel="alternate" hreflang="..." href="...">` per `hreflang_links` item in `{% block head %}` (no `hreflang=` anywhere in the HTML without a public translation), a header (tags linking to `/blog/?tag=<tag>`, title, description, author, publication date, "updated", "verified", reading time, cover), the table of contents as `<details class="blog-toc-wrap">` around `<nav class="blog-toc">` (sticky side column from 1024 px, collapsible below; the text column is capped at `70ch`), and a footer with the "AI version" link to the `.md` twin, the translation links and the related posts. The `blog-*` class hooks are a contract asserted by the tests, attribute order included: `blog-toc`, `blog-meta`, `blog-author`, `blog-published` (`<time class="blog-published" datetime="...">`), `blog-verified`, `blog-reading-time` (`N min czytania` / `N min read`), `blog-tags` / `blog-tag`, `blog-cover`, `blog-related`, `blog-translations`, `blog-md-link` on the post, and `blog-card`, `blog-card-cover` on the list. `blocks.js` (MON-260) takes the first `nav.blog-toc`, opens its `<details>` and adds the class `is-wide` at `(min-width: 1024px)`, and highlights the current section with an `IntersectionObserver` (`rootMargin: "-80px 0px -70% 0px"`; the link of the first visible heading gets the class `is-active` and `aria-current="true"`); without JavaScript the links still work and the `<details>` stays collapsed
- `GET /blog/{slug}/attachments/{attachment_id}/{filename}` - public attachment of a post, looked up through `get_public_post_by_slug`: the current `BlogPost.slug` serves the file, and since MON-271 a previous slug of a public post answers 301 to `/blog/{current slug}/attachments/{attachment_id}/{filename}`, so an image inserted before a slug change keeps working (before, an old slug was 404 here); a previous slug of a private post is still 404. The attachment must belong to that page (`WikiAttachment.wiki_page_id`), otherwise 404. Only PNG, JPEG, GIF and WebP are served `inline`; every other type, SVG included, goes out as `attachment`. Every response, the 301 and the 404 included, carries `X-Content-Type-Options: nosniff`, and a MinIO error is 404
- Dashboard attachment addresses in a post (MON-264): `blog.py::public_page` passes the content through `services/blog.py::rewrite_attachment_urls(content, page_id=..., post_slug=...)` before `render_post_html` / `collect_block_assets`, so an image uploaded in the dashboard editor while the page was a draft is served to an anonymous reader through the public attachment route above. Since MON-271 the markdown twin (`render_post_markdown_document`, so `/llms-full.txt` too) and the three feeds (`_load_feed_entries`) in `blog_ai.py` call it as well, so none of these outputs carries a `/dashboard/` address of an attachment of the post's own page: it goes out as `/blog/<slug>/attachments/...`, made absolute wherever that output already makes its addresses absolute. An attachment of another page and the legacy address `/dashboard/<slug>/wiki/attachments/<file>` are still not rewritten
- `blog_ai.py` (MON-258) - AI layer of the blog: `router = APIRouter(prefix="/blog", tags=["blog-ai"])` with two read-only markdown routes (plus the three feed routes added in MON-259, below), `GET /index.md` declared before `GET /{slug}.md`. `main.py::_register_routers` includes `blog_ai_router` BEFORE `blog_router`, because `/blog/{slug}` in `blog.py` also matches `x.md` and would otherwise swallow both twins. The module imports nothing from `blog.py` or `main.py` (import cycle; `blog.py` imports `conditional_response`, `markdown_twin_response` and `wants_markdown` from it) and builds its own `Response` with `MARKDOWN_MEDIA_TYPE` (`text/markdown; charset=utf-8`), so `_markdown_response` in `main.py` (`/index.md`, `/features/{slug}.md`) is untouched
  - `GET /blog/{slug}.md` - lookup through `get_public_post_by_slug`, like the HTML route: a slug from `previous_slugs` answers 301 to `/blog/{current slug}.md` with the query string preserved; a private post, an unknown slug, a public page without a `BlogPost` row and a MinIO error while reading the content are all 404 (never 403 or 500; the storage error is logged with `logger.exception` in `markdown_twin_response`, which reads the content in an executor)
  - Document: `render_post_markdown_document(post, page, content, translations)`, a synchronous function and the only builder of the document, used by the `.md` route and by `blog.py` for `Accept: text/markdown`. Shape: `---`, the fields, `---`, an empty line, the body and a final newline (frontmatter only when the body is empty). The body is `absolutize_markdown_urls(render_post_markdown(content), APP_URL)`: no HTML added by the server and no `:::` lines. Frontmatter fields, always present and in this order: `title` (`page.title`), `description` (`post.description`, falling back to `extract_summary(strip_block_markers(content))`), `url` (the canonical HTML address `{APP_URL}/blog/{slug}`, `APP_URL` without a trailing `/`), `lang` (`post.lang`), `author` (`post.author_name` or `DEFAULT_AUTHOR_NAME`), `published` (`(post.published_at or page.created_at).isoformat()`), `modified` (`page.updated_at.isoformat()`), `last_verified` (`post.last_verified_at.isoformat()` or `null`), `tags` (list of strings, `[]` when empty), `translations` (list of `{lang, url}` for the other public language versions from `list_public_translations`, `url` being the HTML address, `[]` when none), `reading_time_minutes` (int, `max(1, ceil(word_count / 200))`) and `word_count` (int, `len(body.split())` on the final body)
  - Serialization is manual, with no PyYAML in production code: `pyyaml` is not a production dependency and must not become one (tests may import `yaml`, it is in the dev/CI environment). `_yaml()` writes every string, list and object as `json.dumps(value, ensure_ascii=False)`, i.e. YAML flow style with double-quoted strings, so a quote, a colon or a newline in a title cannot break the document, and additionally replaces every character matched by `_YAML_UNSAFE_CHARS` (the range U+007F-U+009F, plus U+2028 and U+2029) with its four-hex-digit unicode escape, because YAML treats some of them as line breaks and rejects the other control characters. The three dates are quoted strings, so `yaml.safe_load` returns `str` for them, never `datetime`; ints are bare and a missing `last_verified` is a bare `null`
  - `absolutize_markdown_urls(markdown_text, base_url)` prefixes `base_url` (trailing `/` dropped) to every `](...)` target, link or image, that starts with a single `/`. Unchanged: `http://`, `https://`, `mailto:`, `#anchor`, `//host`, paths without a leading `/`, and everything inside fenced code (three or more backticks or tildes, closed by a fence of the same character and at least the same length) and inline code
  - `conditional_response(request, body, *, last_modified, media_type=MARKDOWN_MEDIA_TYPE, headers=None)` adds a strong `ETag`, the first 32 hex characters of sha256 over `last_modified.isoformat() + "\n" + body` (UTF-8, `last_modified` normalized to UTC, a naive value taken as UTC) in double quotes, and `Last-Modified` as an HTTP-date, so the tag changes with the content and with `updated_at`. `If-None-Match` is read as a comma-separated list, a `W/` prefix is ignored in the comparison and `*` always matches; a match answers 304 with an empty body and the same `ETag`, `Last-Modified` and passed `headers`. `If-Modified-Since` is deliberately not implemented
  - `GET /blog/index.md` - one call to `list_public_posts` with `per_page=1000` (no pagination, newest first), `?lang=` and `?tag=` passed through as filters (since MON-260 `/blog/` takes the same two filters, but there an invalid `lang` means no filter instead of an empty list; the interface language of `/blog/` is its `ui` parameter, MON-271). An empty `?lang=` or `?tag=` means no filter. Both are validated before the query, since they come straight from the URL (a value such as NUL would make PostgreSQL fail with a 500): a `lang` outside `POST_LANGS` or a `tag` rejected by `services/blog.py::is_valid_tag()` answers 200 with the empty list and never reaches the database. Body: `# Blog`, then one item per post, `- [<title>]({APP_URL}/blog/{slug}.md) - <YYYY-MM-DD> - <description>` plus ` (tagi: a, b)` when the post has tags; in the title whitespace is collapsed and `\`, `[`, `]` are backslash-escaped, the date is the UTC date of `published_at` (fallback `created_at`), and the description is `post.description` with whitespace collapsed and no MinIO fallback (an empty one drops that part). No posts gives the heading and the line `Brak wpisów.`. It goes through `conditional_response` too, with `last_modified` as the newest `page.updated_at` on the list, or `1970-01-01T00:00:00Z` for an empty list
  - Known limitation: a post whose slug is `index` is not reachable as markdown, because `/blog/index.md` is the list (the slug is not reserved; its HTML page `/blog/index` works)
  - Feeds (MON-259): `GET /blog/feed.xml` (Atom 1.0), `/blog/rss.xml` (RSS 2.0) and `/blog/feed.json` (JSON Feed 1.1), all through `conditional_response` (ETag + 304), with the `FEED_LIMIT = 20` newest public posts and `?lang=` (an invalid value gives an empty feed, like `/blog/index.md`). Atom `content type="html"` and RSS `content:encoded` carry the full rendered HTML (`render_post_html`), the JSON Feed `content_text` the markdown without frontmatter; the teaser (`summary` / `description`) is `BlogPost.description` and is left out when empty. XML is built only with `xml.etree.ElementTree` (no string concatenation, no CDATA; namespaces written as literal attributes, never `ET.register_namespace`, which is process-global) and characters illegal in XML 1.0 are stripped from the text first. Nothing in the body depends on the request time, so the ETag is stable. Content is read for all listed posts at once through `load_post_content(page)` (MON-272), a cache in process memory shared with the `/blog/` list: `page_id -> (updated_at, content)`, one entry per page, a hit only when the stored `updated_at` equals `page.updated_at` (every content write sets it, so a newer save invalidates the entry), otherwise a read from MinIO in the executor; at most `_POST_CONTENT_CACHE_MAX = 256` entries, the oldest inserted one dropped when full. A storage error propagates to the caller and is never cached, so the next request retries; `clear_post_content_cache()` empties the cache (tests). A storage error skips only that post (`logger.error` with the exception, still 200). The `<head>` of every `/blog` page links the three feeds (`layouts/landing.html`, `rel="alternate"`)
  - `build_llms_blog_section(db)` returns the `## Blog` section of `/llms.txt` (`LLMS_BLOG_LIMIT = 10` newest posts as `- [title](base/blog/slug.md): description`, plus the index and Atom feed addresses; empty string without public posts; database only, no MinIO). `main.py::llms_txt` appends it to the static file after one blank line and, on any exception, logs it and answers 200 with the static content alone; the static `static/llms.txt` has no `## Blog` heading. `build_llms_full(db)` backs `GET /llms-full.txt` (`text/plain`): a short header, then one `render_post_markdown_document` per public post, newest first, joined by `LLMS_FULL_SEPARATOR`. The size limit `LLMS_FULL_MAX_BYTES` (1 MB, UTF-8 bytes of the whole document) includes a reserved last line `> Truncated: <omitted> of <total> posts omitted (size limit <limit> bytes). Full list: <base>/blog/index.md`; the first post that does not fit and all later ones are dropped whole and the loop stops there, so MinIO is not read for them. All three constants and `FEED_LIMIT` are read from the module at call time (tests patch them). Since MON-271 the finished `/llms-full.txt` document is kept in process memory under a fingerprint computed by ONE cheap query, with no MinIO read, over the metadata of the public posts (`page_id`, `WikiPage.updated_at`, slug, `lang`, `translation_of_id`, `published_at`, description, tags, author, `last_verified_at`, title) plus the current value of `LLMS_FULL_MAX_BYTES`; an unchanged fingerprint serves the cached document with zero MinIO reads, and a content edit, a metadata change or an unpublish invalidates it through the fingerprint. `blog_ai.clear_llms_full_cache()` (no arguments) empties it, and an autouse fixture in `tests/conftest.py` calls it before every test. `blog.py::public_page` computes `render_post_markdown(content)` once per request and uses it for both `word_count` and the reading time
  - Crawlers and structured data (MON-259): `robots.txt` keeps the `*` group unchanged and adds one separate group for each of `GPTBot`, `ClaudeBot`, `Claude-User`, `PerplexityBot`, `Google-Extended` and `CCBot` with `Allow: /blog/` and the same `Disallow` list, taken from one constant (`_ROBOTS_DISALLOW` in `main.py`), because a named group does not inherit from `*` (RFC 9309). `sitemap.xml` is built with ElementTree and declares `xmlns:xhtml`; a translation group is the public posts sharing a root (`translation_of_id` or the post's own `page_id`), and when it has at least two public posts every `<url>` of the group carries an `xhtml:link rel="alternate" hreflang` for each of them, itself included (a private translation never appears). `services/blog.py::build_post_jsonld(..., structured=None)` adds `FAQPage`, `HowTo` and one `VideoObject` per video to the `@graph` from `extract_structured_data(content)` (only for non-empty lists); `blog.py::public_page` passes it
  - Tests: `tests/integration/test_blog_ai.py` (both routes, negotiation, JSON-LD in the pages, conditional requests) and `tests/unit/test_blog_service.py` (JSON-LD builders, `dump_jsonld`, `list_public_translations`)

## Decisions

- Blog AI layer (MON-258): every public post has a markdown twin at `/blog/{slug}.md` (YAML frontmatter + body with absolute URLs) and the list has one at `/blog/index.md`, both in `blog_ai.py`, whose router must be registered before `blog.py`'s, since `/blog/{slug}` would match the `.md` addresses. One function, `render_post_markdown_document()`, builds the document for the `.md` route and for `/blog/{slug}` with `Accept: text/markdown`, so both addresses return the same body and the same `ETag`; HTML points at the twin through `<link rel="alternate" type="text/markdown">` and a `Link` header, and varies on `Accept`. The frontmatter is serialized by hand as YAML flow style (`json.dumps` per value) instead of adding `pyyaml` as a production dependency. Caching is `ETag` + `Last-Modified` with `If-None-Match` only (`conditional_response()`), no `If-Modified-Since`. Structured data (`BlogPosting` + `BreadcrumbList` on a post, `Blog` on the list) is built as a `dict` in `services/blog.py` and neutralized in Python by `dump_jsonld()` before the template prints it with `|safe`. Known limitation: the slug `index` is not reserved, so a post with that slug has no `.md` twin (`/blog/index.md` is the list)
- Blog pages for people (MON-260): the post page and the list are plain server-rendered templates with one stylesheet, `static/blog/blog.css` (no inline `<style>`, light and dark theme through the `.dark` class of `layouts/landing.html`, long words wrapping (`overflow-wrap: anywhere` on `.blog-content`), while a table and a `<pre>` keep normal word breaking and scroll inside their own box with `overflow-x: auto`, so that a narrow screen does not scroll the page horizontally), loaded before `blocks.css`. Everything the templates show is computed in Python and passed as context: the table of contents is parsed from the rendered HTML (the anchors of the block engine, never a second slug computation) and omitted below 3 H2/H3 headings, reading time is 200 words per minute, related posts are public posts of the same language ranked by shared tags and then recency. On the list, `?tag=` and `?lang=` are validated before the query and kept by every pagination link, the interface language comes from `?ui=` and not from the `lang` filter (MON-271), each pagination page is its own canonical with `rel="prev"` / `rel="next"`, and a post with a public translation gets `hreflang` links for every language version. Both HTML responses reuse `conditional_response()` from the AI layer (`ETag`, `Last-Modified`, 304). The `blog-*` class names in the templates are hooks asserted by the tests, so renaming one is a contract change.
