# Architecture: services/blog.py and the blog_posts model

Detail moved out of CLAUDE.md. Account-level `blog:write` permission: `arch-rbac-mcp.md`.

- `services/blog.py` (MON-254) - blog post metadata, one `BlogPost` row per wiki page; results are the model or a `@dataclass` (`PublicPost`, `PublicPostLookup`, `PublicPostList`, `BlogPostView`, `BlogPostDetail`, `PublishResult`), business errors are `ValueError`. `ensure_post(db, page)` is idempotent: it creates the row with `slug = page.slug` and the column defaults, or returns the existing one without ever changing its slug, and sets `published_at` to now (UTC) when the page is public and the date is still empty; a slug already taken by another post (its `slug` or its `previous_slugs`) is a `ValueError`, and so is, since MON-272, a page slug longer than `SLUG_MAX_LENGTH` (255; `wiki_pages.slug` holds 512, `blog_posts.slug` 255) when the row has to be created: `Slug strony jest za długi dla wpisu bloga (max 255 znaków). Skróć tytuł strony.` instead of a database error (422 in API v2, error text in MCP, a flash in the dashboard). It only does `db.add` + `db.flush` and does NOT commit, because it runs inside the transaction of its caller (`create_wiki_page` / `update_wiki_page`, and since MON-263 `publish_post`). `get_public_post_by_slug(db, slug)` returns the post and page for a current slug, a `redirect_slug` for a slug found in `previous_slugs`, and `None` otherwise; both paths filter `WikiPage.is_public` in SQL, so an old slug of a private post does not reveal that it exists. Since MON-271 it validates the slug first: an empty slug, one longer than 255 characters or one that does not match the slug pattern returns `None` with no database query, so `/blog/%00`, `/blog/%00.md` and `/blog/%00/attachments/<uuid>/<file>` are all 404. `list_public_posts(db, page, per_page, tag=None, lang=None)` returns public posts ordered by `published_at DESC NULLS LAST`, then `slug ASC` (stable pagination), with an out-of-range `page` clamped to `1..total_pages`. `set_post_meta(db, user, project, page_id, *, ...)` follows the `(db, user, project, ...)` convention of `services/projects.py` and commits itself: it opens with `ensure_permission()` for `wiki:write` and then `ensure_blog_permission()` (`blog:write`, MON-270), both before the page lookup; the page must belong to the project (`Strona wiki nie istnieje`); a missing row is created through `ensure_post`, or, since MON-272, directly with the `slug` from the call when one is passed (the collision check then covers only that new slug, and the page slug, which was never a public address, does not enter `previous_slugs`); an omitted field (`_UNSET` sentinel) stays unchanged, and `is_public` is never touched. Validation: `description` max 300 characters after `strip()`, `lang` only `pl` / `en`, `tags` max 10 slug-shaped items of max 50 characters with duplicates dropped, `author_name` non-empty and max 255, `cover_attachment_id` must be an attachment of the same page, `translation_of_id` must point at an existing post other than itself and, since MON-271, passes four more checks in this order, each a `ValueError`: the target is missing or belongs to another project (`Wpis wskazany jako oryginał nie istnieje`, one text for both cases), the target is itself a translation (`Wpis wskazany jako oryginał jest tłumaczeniem innego wpisu`), the target has the same language as the effective language of the edited post (`Tłumaczenie musi być w innym języku niż oryginał`), or the edited post already has translations of its own (`Wpis ma tłumaczenia, więc nie może być tłumaczeniem innego wpisu`); existing rows are not migrated. Since MON-272 the language rule also holds for every effective change of `lang` on an existing row (the new value differs from the current one), whether `translation_of_id` is omitted, passed as an explicit `None` (the dashboard form always sends both fields) or equal to the current link: the same `Tłumaczenie musi być w innym języku niż oryginał` when the post has a translation already written in the new language (checked when `translation_of_id` is omitted or `None`), or when the post is a translation, the link stays (omitted or the same value) and the new language equals its original's. An explicit `None` clears the link, so the original's language is not checked then, and a new `translation_of_id` value goes through the four checks above, unchanged. Stable-slug rule: the slug is set once, at row creation, and changes only through an explicit `slug` in `set_post_meta`, which appends the old slug to `previous_slugs` and rejects a slug that is the slug or a previous slug of another post; a title change never changes it. The `slug` format is checked with `fullmatch` of the slug pattern (MON-272, max 255 characters), so a trailing `\n` or `\r` and any character outside the pattern are rejected (`Slug jest nieprawidłowy: ...`), in MCP `set_blog_post_meta`, the v2 PATCH and the dashboard form alike. JSONB lists (`tags`, `previous_slugs`) are replaced by assignment, never mutated in place, or SQLAlchemy does not persist the change. MON-258 adds `is_valid_tag(value: str) -> bool` (length at most `TAG_MAX_LENGTH`, i.e. 50, and a `fullmatch` of the slug pattern), shared by the tag validation of `set_post_meta` and by the `?tag=` filter of `/blog/index.md`; because it uses `fullmatch`, a tag with a trailing newline is now rejected. It also adds four read-only functions for the AI layer. `list_public_translations(db, post)` returns the other public posts of the same translation group (root = `post.translation_of_id or post.page_id`; the root and every post with `translation_of_id == root`, without `post` itself), ordered by `lang`, then `slug`, with `WikiPage.is_public` filtered in SQL so a private translation never reaches the frontmatter; no commit. `build_post_jsonld(post, page, *, base_url, description, word_count=None, image_url=None)` and `build_blog_jsonld(posts, *, base_url)` are pure (no IO) and return a `dict`: the first `{"@context": "https://schema.org", "@graph": [BlogPosting, BreadcrumbList]}`, where `BlogPosting` has `headline`, `description`, `datePublished`, `dateModified`, `author` (`Person`), `inLanguage`, `mainEntityOfPage` (`WebPage` with `@id` = `{base_url}/blog/{slug}`) and `url`, plus `keywords` (when the post has tags), `wordCount` and `image` (when passed), and `BreadcrumbList` has two `ListItem`s (`Blog` -> `{base_url}/blog/`, the title -> the post URL); the second a `Blog` with `url` and `blogPost[]` (`BlogPosting` with `headline`, `url`, `datePublished`, `inLanguage`, and `description` only when non-empty). Both strip a trailing `/` from `base_url`. `dump_jsonld(data)` is the only way that JSON reaches a template: `json.dumps(data, ensure_ascii=False)` with every `<` replaced by the six-character JSON escape `\u003c` (which removes `</script>` and `<!--`) and raw U+2028 / U+2029 replaced by their six-character escapes `\u2028` / `\u2029`, so the result still parses with `json.loads` to the same data. MON-261 adds the authenticated reads behind `list_blog_posts` / `get_blog_post` (MCP, API v2, CLI), both opening with `ensure_permission()` for `wiki:read`: `list_posts(db, user, project, status=None)` returns a `BlogPostView` for every page of the project that has a `BlogPost` row, drafts (`is_public=false`) included, in the order of `list_public_posts`; `status` is `published`, `draft` or `None` (all), anything else is `ValueError("Nieprawidłowy status: dozwolone published, draft")`, and a wiki page without a row is not listed. `get_post(db, user, project, page_id, *, content_fn=None)` returns a `BlogPostDetail` (the view plus `content`) and is a pure read: a page outside the project is `Strona wiki nie istnieje`, a page without a row is `Wpis bloga nie istnieje` (it never calls `ensure_post`); `content_fn` is injectable like in `get_wiki_page_detail` and resolved at call time, because `services/wiki.py` imports `ensure_post` from this module and a module-level import back would be a cycle. `build_post_view(post, page)` is a pure helper (no DB, no permission check) shared by the reads and by the adapters after `set_post_meta`: `title` and `is_public` come from the page, and `public_url` (`{APP_URL}/blog/{slug}`) and `markdown_url` (`public_url` + `.md`) are set only for a public page. `markdown_url` is only the address: this ticket adds no route that serves it. MON-260 adds four read-only helpers for the human-facing templates (no write, no commit). `extract_toc(content_html) -> list[TocEntry]` (`TocEntry` is a frozen dataclass `level`, `id`, `text`) reads H2 and H3 that carry an `id` from the rendered HTML, in document order, with tags stripped from the text and entities unescaped; it reuses the anchors written by `blog_blocks._anchor_headings` instead of computing slugs a second time, and returns `[]` below `TOC_MIN_ENTRIES` (3 headings, H2 + H3 together). `reading_time_minutes(text) -> int` is `max(1, ceil(words / WORDS_PER_MINUTE))` with 200 words per minute and words split on any whitespace. `list_related_posts(db, post, limit=3) -> list[PublicPost]` returns only public posts (`WikiPage.is_public` in SQL) in the same `lang`, never the post itself: first the posts sharing at least one tag, ordered by the number of shared tags descending and then `published_at DESC NULLS LAST`, `slug`; remaining places are filled with the newest posts of that language, so a shared tag is not required. `get_cover_urls(db, posts) -> dict[uuid.UUID, str]` maps `page_id` to the relative path `/blog/{slug}/attachments/{attachment_id}/{quote(filename)}` in exactly one query, skipping posts without a cover and covers that are not an attachment of the post's own page. MON-264 adds `rewrite_attachment_urls(markdown_text, *, page_id, post_slug) -> str`, a pure function (no DB): it replaces `/dashboard/<any project slug>/wiki/pages/<page_id>/attachments/<attachment_id>/<filename>` with `/blog/<post_slug>/attachments/<attachment_id>/<filename>` ONLY when the `<page_id>` in the address equals the `page_id` argument. An attachment address of another page and the legacy `/dashboard/<slug>/wiki/attachments/<filename>` stay unchanged, so a post cannot expose another page's attachment through its own public route. Called by `blog.py::public_page`; the dashboard form (`dashboard/wiki.py`) calls `set_post_meta` from this module for the "Wpis na blogu" section. MON-263 adds the two publication functions behind `publish_blog_post` / `unpublish_blog_post` (MCP, API v2, CLI), both opening with `ensure_permission()` for `wiki:write` and then `ensure_blog_permission()` for the account-level `blog:write` (MON-270, in this order), before the page lookup and before the lint, and both committing in the service. `publish_post(db, user, project, page_id, *, force=False, content_fn=None) -> PublishResult` (a dataclass with `view: BlogPostView` and `lint: LintResult`): page lookup (`Strona wiki nie istnieje`), `ensure_post` (the lint needs the row, so a missing one is created), then `blog_lint.lint_post_by_id`, imported at call time because `blog_lint` imports `DESCRIPTION_MAX_LENGTH` from this module, with `content_fn` passed through; `lint_post_by_id` checks `wiki:read` itself, so publishing needs `wiki:write`, `blog:write` and `wiki:read`. With lint errors and `force=False` it rolls back (a row created a moment earlier does not stay) and raises `ValueError("Publikacja odrzucona: wpis ma błędy lintu (<n>): <rule> (linia <line>), ... Napraw je albo użyj force.")`, listing only the rules of level `error`, without the line part when the line is 0. Otherwise it sets `page.is_public = True`, calls `ensure_post` again, which fills `published_at` only when it is empty (a second publication and a publication after an unpublish keep the date and the address), and commits; an `IntegrityError` from the global partial unique index `uq_wiki_public_slug` (a public page with the same slug in another project) becomes, after a rollback, the `ValueError` `Strona publiczna o slugu '<slug>' już istnieje w innym projekcie. Zmień tytuł strony przed publikacją.`, the same text as in `update_wiki_page`, and a `ValueError` from `ensure_post` (slug taken by another post) is rolled back and re-raised. `unpublish_post(db, user, project, page_id) -> BlogPostView` sets `is_public = False` and leaves `published_at` and the slug alone, so publishing again restores the same address; a page outside the project is `Strona wiki nie istnieje`, a page without a `BlogPost` row is `Wpis bloga nie istnieje`, and an already private post is not an error. The `is_public` parameter of `create_wiki_page` / `update_wiki_page` and the dashboard checkbox stay as the lower level of publishing, without the lint gate but, since MON-270, behind the same `blog:write` check (in `services/wiki.py`). The reads (`list_posts`, `get_post`, and `lint_post_by_id` in `services/blog_lint.py`) stay on `wiki:read` alone. Pages and posts that were public before MON-270 stay public; there is no data migration

## Decisions

- Public blog (MON-254): post metadata lives in `blog_posts`, 1:1 with `wiki_pages` (`page_id` is both the primary key and the foreign key, `ON DELETE CASCADE`); `models/wiki_page.py` has no relationship to it, queries join explicitly. `WikiPage.is_public` stays the only exposure switch: a `BlogPost` row alone publishes nothing. The post slug is set once, when the row is created (at first publication, or at the first `set_post_meta` on a page that is not public yet), copied from the wiki slug, or taken from the `slug` of that first `set_post_meta` call when it passes one (MON-272), and from then on is independent of the page title and of the wiki slug; it is unique globally (`uq_blog_posts_slug`), not per project, and an explicit change keeps the old value in `previous_slugs`, which `/blog/{slug}` answers with a 301. Migration `j1e2f3a4b5c6` creates only this table and backfills a row for every already public page (`slug` = page slug, `published_at` = `created_at`, `lang` = `pl`), so addresses that worked before keep working. The backfill skips a public page whose slug is longer than 255 characters (MON-272, `char_length(slug) <= 255`): it stays `is_public` without a `blog_posts` row, so its public address answers 404 until the title is shortened (truncating the slug would risk a unique-index collision and change the address). `/sitemap.xml` (`main.py::sitemap_xml`) lists `/blog/` and one URL per public post taken from `BlogPost.slug`, with `lastmod` as the later of the page's `updated_at` and `last_verified_at` (MON-271): `updated_at.isoformat()` when `last_verified_at` is empty or not later than the date of `updated_at`, `last_verified_at.isoformat()` when it is later; `published_at` takes no part
