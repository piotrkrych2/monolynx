How to MCP

Podłącz Claude Code do Monolynx przez MCP i zarządzaj Scrumem z poziomu terminala

1

Wygeneruj token API

Przejdź do strony Tokeny API, nadaj tokenowi nazwę (np. "Claude Code") i kliknij Wygeneruj token.

Skopiuj token od razu — nie będzie wyświetlony ponownie.

2

Dodaj serwer MCP do Claude Code

Dodaj do pliku .mcp.json w katalogu projektu:

{ "mcpServers": { "monolynx": { "command": "npx", "args": [ "-y", "mcp-remote", "{{ app_url }}/mcp/", "--header", "Authorization: Bearer TWOJ_TOKEN" ] } } }

Zastąp TWOJ_TOKEN wygenerowanym tokenem API (zaczyna się od osk_).

2b

Alternatywa: Claude Desktop (OAuth)

zamiast 2

Claude Desktop obsługuje MCP przez OAuth — nie potrzebujesz tokenu API. Otwórz Settings → Integrations → Add i wypełnij pola:

Nazwa connectora Monolynx
URL connectora {{ app_url }}/
OAuth Client ID zostaw puste
OAuth Client Secret zostaw puste

Claude Desktop automatycznie zarejestruje się jako klient OAuth i przekieruje Cię do strony logowania Monolynx. Zaloguj się swoimi danymi (email + hasło) i zatwierdź dostęp.

Jak to działa? Claude Desktop odkrywa endpointy OAuth przez /.well-known/oauth-authorization-server, rejestruje klienta (Dynamic Client Registration), a następnie przeprowadza flow PKCE. Pola Client ID i Secret są opcjonalne — wypełniaj je tylko jeśli masz wcześniej zarejestrowanego klienta.

Użyj narzędzi

Po połączeniu Claude Code ma dostęp do 94 narzędzi we wszystkich modułach:

Projekty

  • list_projects — lista projektów
  • get_project_summary — podsumowanie projektu
  • get_project — pełne szczegóły projektu
  • create_project — utwórz nowy projekt
  • update_project — edytuj projekt
  • delete_project — usuń projekt

Członkowie zespołu

  • list_members — lista członków projektu
  • invite_member — zaproś do projektu
  • remove_member — usuń z projektu

Role (RBAC)

  • list_roles — lista ról z uprawnieniami
  • create_role — utwórz rolę z matrycą uprawnień
  • update_role — edytuj rolę
  • delete_role — usuń rolę (nie systemową)
  • assign_role — przypisz rolę członkowi
  • get_member_permissions — sprawdź uprawnienia

500ki (błędy)

  • list_issues — lista błędów
  • get_issue — szczegóły błędu
  • update_issue_status — zmień status
  • create_ticket_from_issue — utwórz ticket z błędu

Scrum — Etykiety

  • list_labels — lista etykiet projektu

Scrum — Sprinty i tablica

Komentarze i czas pracy

  • list_comments — komentarze do ticketu

Rozliczenia — CRUD

  • link_ticket_to_settlement — podepnij ticket (tylko draft)

Rozliczenia — Załączniki

  • add_settlement_attachment — upload base64 do MinIO
  • get_settlement_attachment — pobierz plik jako base64
  • delete_settlement_attachment — usuń załącznik (tylko draft)

Monitoring

  • list_monitors — lista monitorów
  • get_monitor — szczegóły monitora
  • create_monitor — utwórz monitor

  • delete_monitor — usuń monitor

Audyt

Heartbeat

  • list_heartbeats — lista heartbeatów

Połączenia (graf)

  • get_graph_node — szczegóły node'a

4

Zainstaluj skille Claude Code

Rekomendowane

install_monolynx_skills

MCP tool

Flagowy sposób instalacji — działa w dowolnym projekcie podłączonym do Monolynx MCP. Claude pobiera skille przez MCP i zapisuje je do .claude/skills/. Placeholdery <PROJECT-SLUG> / <PROJECT-ID> są automatycznie podmieniane na slug Twojego projektu.

Użycie w Claude Code / Claude Desktop — jeden prompt:

Zainstaluj domyślne skille Monolynx dla projektu moj-projekt.

Pod spodem Claude wywołuje MCP w dwóch krokach:

install_monolynx_skills(project_slug="moj-projekt") // → catalog dostępnych skilli install_monolynx_skills( project_slug="moj-projekt", skill_names=["monolynx-work", "monolynx-help", ...] ) // → pełna treść skilli → Claude zapisuje je do .claude/skills/
brak ręcznego ZIP-a placeholder → slug auto selektywnie lub wszystkie
Alternatywa: ręczne ZIP-y (gdy nie masz połączenia MCP)

Pobierz paczkę i rozpakuj w katalogu głównym projektu — pliki trafią do .claude/skills/. Po rozpakowaniu podmień <PROJECT-SLUG> na slug Twojego projektu ręcznie.

Dostępne skille

monolynx-help

Wyświetla przewodnik po wszystkich skillach Monolynx — flow pracy z ticketami i skille dodatkowe. Zacznij tutaj.

Użycie: /monolynx-help

monolynx-work

Koordynator zespołu agentów — podejmuje ticket ze sprintu, rozdziela pracę, loguje czas.

Użycie: /monolynx-work [ticket-id]

monolynx-search

Wyszukiwanie semantyczne w wiki projektu (RAG). Aktywuje się automatycznie na pytania o dokumentację.

Użycie: /monolynx-search jak działa autoryzacja w API?

monolynx-create-graph-ci-script

Generuje skrypt CI synchronizujący graf zależności kodu z Twojego projektu.

Użycie: /monolynx-create-graph-ci-script

monolynx-ticket-create

Tworzy nowy ticket z pełnym kontekstem — zbiera informacje z wiki, kodu i grafu zależności, generuje opis w ustalonej formie.

Użycie: /monolynx-ticket-create dodaj eksport CSV w raportach

monolynx-ticket-review

Recenzuje ticket przed podjęciem pracy — sprawdza formę, zgodność założeń z wiki i kodem, generuje raport z oceną.

Użycie: /monolynx-ticket-review [ticket-id]
